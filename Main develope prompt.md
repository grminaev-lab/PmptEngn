Задание на разработку приложения. 
Определяет основные требования к функционалу, стеку разработки, архитектуре решения.
Промпт:
Ты - fullstack-разработчик. Будешь делать проект по разработке веб-приложения по асинхронному опросу AI агентов, созданных в yandex AI studio. Параметры опроса задаются пользователем через веб-интерфейс. Результаты сохраняются в базу данных и могут быть просмотрены в веб-интерфейсе на отдельной странице. 

Общий алгоритм работы программы:

Страница веб-интерфейса с параметрами опроса "Request parameters"
Пользователь задаёт:
1) Температуру. // примечание - Для установки значения использовать связку slider и entryfield.
2) Максимальное количество токенов.
3) Системный Промпт.
4) Текст запроса. 

Также пользователь отмечает, какиих агентов он хочет опрашивать. Перечень агентов представлен в виде списка (listbox-source) на левой стороне экранной формы. Агенты для опроса переносятся пользователем в итоговый список (listbox-destination) на правой стороне экранной формы с помощью кнопки (>), также с помощью кнопки (<) можно убрать выбранного агента обратно в listbox-source. Доступны функции:
- перенести всё из listbox-source в listbox-destination по кнопке (>>),
- перенести всё из listbox-destination в listbox-source по кнопке (<<).

Названия доступных агентов и данные для доступа к ним хранятся в файле конфигурации (config.json).

Запуск опроса запускается по нажатию кнопки (Start requests). На время работы опроса, кнопка (Start requests) дизейблится.

При первоначальной загрузке страницы "Request parameters" температура, максимальное количество токенов, системный промпт и текст запроса устанавливаются в значения по умолчанию, которые храняться в файле конфигурации (config.json). Из конфигурационного файла считываются названия доступных агентов и формируется список listbox-source.

Кнопка (Save settings) позволяет сохранить текущие параметры (температура, максимальное количество токенов, системный промпт и текст запроса) в конфигурационный файл.

На странице "View results":
1) Можно просмотреть результаты опросов, выбрав из списка сохранённых опросов. Список формируется из данных поля Request_ID (уникальный номер опроса ) +": "+ date (дата опроса) + "/" + time (время опроса с точностью до секунды).
По умолчанию выводятся данные последнего сохранённого опроса.
Выводимые данные:
1. Парметры опроса (температура, максимальное количество токенов, системный промпт, текст запроса)
2. Ответы агентов. Выводить в текстовое поле в формате ("Agent: " + имя агента, /* перенос строки */ "Response: " + текст ответа). Ответы всех агентов выводятся в одно поле со скроллом. Вывод форматировать для удобства чтения.

2) Доступна функция сохранения результатов выбранного опроса в файл формата json по кнопке (Save as json). Сохранять в папку приложения в подпапку Results. Имя файла = {RequstID+date}.json. Сохранять все выводимые данные: параметры опроса, ответы агентов.

Работа кнопки (Start requests). 
1. Блокируется кнопка (Start requests).
2. В базе данных делается запись об опросе и его параметрах.
3. Осцществляется асинхронный опрос выбранных агентов с использованием текущих параметров, заданных пользователем на странице "Request parameters".
4. В базу данных записываются ответы каждого опрошенного агента или сообщение об ошибке, если сеанс с агентом завершён по таймауту (таймаут задаётся в файле конфигурации) или связь с агентом отсутствует.
5. Пользователю выводется сообщение "Session complited. Please check results."
6. Разблокируется кнопка (Start requests).

Структура БД:
Таблица Requests
Поля:
Request_ID - первичный ключ, автоинкремент
    Req_Date - дата и время опроса
Таблица Responses
Поля
    Resp_ID - первичный ключ, автоинкремент
    Req_ID - внешний ключ - Request_ID из таблицы Requests
    Agent_Name - имя агента, текстовое поле
    Resp_Text - текст ответа, текстовое поле
